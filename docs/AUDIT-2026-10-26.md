# Audit — Sync it 0.2.1 (branch codex/quick-updates, commit 13f044a)

Date: 2026-10-26. Scope: all tracked source (`electron/`, `src/`, `shared/`, `scripts/`, CI, docs), dependency audit, and empirical checks on this Windows host. Not covered: macOS execution, physical two-machine LAN pairing, the Electron UI suites (`test:ui`, `test:features`, `test:updates`), which open real windows and were deliberately not run.

## What was verified

| Check | Result |
| --- | --- |
| `npm run typecheck` | clean |
| `npm test` (core, security, control, updates) | 22 / 22 pass |
| `npm run test:sync` (two real Syncthing engines + unapproved third device) | pass, 63 s; small note reached peer in 2.1 s |
| `npm audit` | 0 vulnerabilities |

Design points that hold up on review: IPC sender/frame/origin checks (`main.ts:218-222`); path containment with per-segment symlink walk (`files.ts`); the loopback control endpoint (random port, 256-bit bearer token, timing-safe compare, Host and Origin checks, size/time/concurrency limits, Map-based dispatch so no prototype keys); the Syncthing lockdown (no global announce, relays, NAT, STUN, usage reporting, crash reporting or auto-upgrade; loopback GUI with random API key and bcrypt password; `allowedNetworks` restricted to attached IPv4 subnets plus `!0.0.0.0/0`, `!::/0`); Electron fuses and sandboxed, context-isolated renderer with a deny-by-default `webRequest` filter and CSP; update selection and SHA-256 re-verification before launch.

## Findings

### HIGH

**1. The macOS "engine" is a 1.7 KB FreeBSD rc shell script, not Syncthing.** `scripts/fetch-engine.mjs:35` picks the first zip entry whose name ends with `/syncthing`. In the macOS archives that is `etc/freebsd-rc/syncthing`, which sorts before the real top-level `syncthing` binary. Both `vendor/mac-x64/syncthing` and `vendor/mac-arm64/syncthing` are that script (`file` reports "POSIX shell script"), and the `darwin-*` entries in `shared/engine-integrity.json` pin the script's hash, which is why the two architectures share one hash. Any Mac build produced by `dist:mac` ships an engine that cannot run, and the integrity check would pass on the wrong file. Windows is unaffected because only one entry ends with `/syncthing.exe`. The real binaries hash to `71a05d97…` (amd64) and `38aab770…` (arm64).
Fix: match the exact top-level entry (`entryName === `${archiveStem}/${basename}``), fail if the extracted file is under a few MB, regenerate the darwin pins, and add that size check to the test the integration suite already does for a modified helper.

### MEDIUM

**2. System tools are resolved through PATH.** `electron/security.ts:27-31` runs `whoami.exe` and `icacls.exe` by bare name. Demonstrated here: under a Git Bash PATH, `whoami.exe` resolves to GNU coreutils and `secureDirectory` throws, so `test:sync` fails from that shell and the packaged app would abort startup with "Sync it could not start" for any user whose PATH shadows those names. It is also a classic PATH-hijack surface for the one privileged-looking operation the app performs. Use `path.join(process.env.SystemRoot ?? 'C:\Windows', 'System32', …)`.

**3. Downloaded installers are never removed.** `electron/updates.ts:63-66` creates `userData/updates/download-*` per download and deletes it only on failure. A verified installer (up to 600 MB) stays after install or after the user postpones and restarts, and nothing prunes the directory at startup, contradicting `docs/UPDATES.md` ("held only for the current app session"). Clear `updates/` at startup and after a successful hand-off.

**4. Local note history and thumbnail cache grow without bound.** `electron/library.ts:479-482` writes the full previous text to `note-recovery/` on every save whose text changed, and the editor autosaves 600 ms after typing stops (`src/NoteEditor.tsx:206`). An editing session on a large note multiplies its size by the number of pauses. `docs/SECURITY.md` says so, but a retention cap (last N versions per note, or an age limit) is cheap. The thumbnail cache (`main.ts:140`) also keeps every past mtime/size variant forever.

**5. Hard-link dependency breaks collections on exFAT/FAT32.** `atomicWrite(…, replace=false)` (`files.ts:40`) and `importFiles` (`library.ts:437`) rely on `fs.link`, so creating notes, pasting images and importing files fail on volumes without hard links, which is common for external drives. `chooseRoot` does not warn. Fall back to `rename` with an `wx` existence check when `link` returns `EPERM`/`ENOTSUP`, or reject such roots with a clear message.

### LOW

**6.** `assertSafeToOpen` allows `.odt/.ods/.odp` (ODF files can carry LibreOffice macros), `.rtf`, `.pdf` (JavaScript) and archives, while excluding `.docm/.xlsm`. Consistent policy would drop the ODF trio or document the reliance on the viewer's macro prompt. (`electron/security.ts:9`)

**7.** `runGitHub` collapses every failure into one message (`updates.ts:93`), hiding "not logged in" vs "offline" vs "rate limited". Separately, when `LOCALAPPDATA` is unset the candidate becomes the cwd-relative `Programs\GitHub CLI\gh.exe` (`updates.ts:84`); skip the candidate instead.

**8.** `cleanName` strips trailing dots/spaces before truncating to 160 characters (`files.ts:30`), so a long name whose 160th character is a space is later rejected by `safeRelative` as "unsafe filename". Strip after slicing.

**9.** `recoverOrphan` compares the helper's reported config path case-sensitively (`sync-engine.ts:135`); on Windows a case difference yields the misleading "Another service is using this control port" error.

**10.** The engine restart budget `retries < 3` (`sync-engine.ts:121`) is never reset after a healthy run, so after three crashes over the app's lifetime supervision stops until a manual retry.

**11.** Trashing an item leaves its path in `favorites` (`main.ts:265`), while rename updates it (`main.ts:264`). Bounded at 5000 entries, so cosmetic.

**12.** `.github/workflows/desktop.yml` pins actions by major tag (`@v4`) rather than commit SHA.

**13.** Defense in depth only: `importFiles` accepts any absolute path from the renderer (`main.ts:245`). A compromised renderer could copy any user-readable file into the synced collection. The renderer has no network, strict CSP and no remote content, so this is noted, not rated.

**14.** `decodeURIComponent` in the `syncit-app` handler (`main.ts:120`) throws on malformed percent sequences, producing an unhandled rejection instead of a 404.

## Documentation drift

`docs/TESTING.md` reports the macOS engine as "unverified"; finding 1 means it is known broken until the fetch script is fixed. `docs/UPDATES.md` overstates download cleanup (finding 3).

## Resolution (same day)

All fourteen findings were addressed in the working tree after the audit:

| # | Change |
| --- | --- |
| 1 | `fetch-engine.mjs` extracts the exact top-level entry, checks size and PE/Mach-O magic, and fails on a runtime-pin mismatch (`--write-pins` to upgrade). Darwin pins regenerated: amd64 `71a05d97…`, arm64 `38aab770…`. `sync-engine.ts` restores the execute bit on the verified helper. |
| 2 | `security.ts` runs `whoami.exe` and `icacls.exe` from `%SystemRoot%\System32`. |
| 3 | `Updates.clean()` removes `userData/updates` at startup; a download held by the current session is kept. |
| 4 | `Library.pruneRecovery()` keeps 20 versions per note and 30 days; `pruneThumbnails()` drops thumbnails older than 30 days at startup. |
| 5 | `linkOrClaim()` falls back to an exclusive `wx` claim plus rename when hard links are unsupported; used by `atomicWrite` and imports. |
| 6 | `.odt/.ods/.odp` removed from the launch allowlist. |
| 7 | `describeGitHubFailure()` maps gh failures to actionable messages; candidates with unset environment variables are skipped. |
| 8 | `cleanName` strips trailing dots/spaces after truncation. |
| 9 | Orphan-helper path comparison is case-insensitive on Windows. |
| 10 | Restart budget resets after 60 s of healthy running. |
| 11 | Trashing an item removes it from favorites. |
| 12 | Actions pinned to commit SHAs (checkout v4.4.0, setup-node v4.4.0, upload-artifact v4.6.2). |
| 13 | `importFiles` refuses paths inside private app storage. |
| 14 | Malformed percent-encoding in app URLs returns 404. |

Also added: in-app updates for macOS (selects and verifies `Sync-it-VERSION-mac-ARCH.dmg`, opens the disk image, quits); explicit ad-hoc signing for macOS bundles (`identity: "-"`, `hardenedRuntime: false`), since electron-builder performs no ad-hoc fallback for `identity: null` and Apple Silicon will not launch an unsigned repackaged bundle; and a post-build check in `scripts/build-mac.sh` for signature validity and the bundled helper's pin. Verified after the changes: typecheck clean, 25 unit tests pass, two-engine integration suite passes. Not verified: Electron UI suites, any Mac execution.

## Side effects of this audit

The packaged 0.2.1 build was launched six times in throwaway profiles under `.cache/` and the session scratchpad; each instance ran its own Syncthing for under a minute with local discovery on, then was quit or killed. The installed app and its profile under `%APPDATA%\Sync it` were not touched (verified by process list and file mtimes). All throwaway profiles were removed.
